# Editor pass results

Generated by `the_measured_numbers_are_recorded` in `crates/cli/tests/editor_pass.rs`. **The whole file is rewritten** every time `scripts/check.sh` runs, so nothing added here by hand survives; a plain `cargo test` leaves the file alone. Why each measurement exists is in [`manual-testing-zed.md`](manual-testing-zed.md).

Measured against a **debug** build, because that is what `cargo test` builds. The classpath figures below are therefore not comparable with the ones in [`performance.md`](performance.md), which are release numbers.

The reparse samples are the **always-incremental** shape: each keystroke waits for its own reparse, which is what makes them countable at all, and that excludes by construction the path where an edit arrives before the previous reparse lands and `JavaParser::reparse` falls back to a full parse. The p95 below is the optimistic branch.

Every duration is an **upper bound in whole units**, not a measurement — `< 1 ms` means the run came in under a millisecond and nothing finer. [`performance.md`](performance.md) is where precise figures live. These are rounded because this file is regenerated by the gate and committed: timings never repeat, so a precise one would report "the numbers moved" on every single run and teach its reader to ignore the one time they did. The sample count is exact — it is a count, and its being visible is the point.

The cold classpath read carries no duration at all. It is seconds long, so a bound loose enough not to flap on a loaded machine would say nothing, and it is the one figure here that nothing waits on. The **release** figure for it is in [`performance.md`](performance.md) — a different measurement from the debug one withheld here, not the same number written down elsewhere. What this row claims is that the warm read comes from the cache instead, which is the whole point of having one.
